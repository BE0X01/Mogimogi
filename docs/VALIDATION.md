# 검증 기록

작성: 2026-09-26 KST

## 이 환경에서 확인한 내용

- Linux에서 .NET SDK 10.0.100으로 Windows 대상 WinForms 프로젝트 컴파일 성공.
- 빌드 경고 0개, 오류 0개.
- ClosedXML 0.105.0으로 샘플 Excel 3개, 총 20문제를 실제 읽어 검증.
- 실행형 검증 17개 통과: 헤더/빈 행, 자동 및 고정 ID, 오류 행, 손상 파일 격리, ID 충돌, 중복 없는 출제, 개수 제한, 선지 셔플과 ID 채점, 중복 제출 차단, 저장 실패 재시도, JSON 재시작·백업·중복 방지, 손상 기록 보존, 파일 잠금, 통계·오답 조회.

Windows GUI를 실제로 실행한 결과는 아닙니다. Windows Forms 런타임 화면, DPI, Windows 파일 교체 동작은 아래 절차로 확인해야 합니다.

## Windows에서 첫 실행 확인

1. `run.cmd` 실행 후 분류에 어휘·독해가 나타나는지 확인합니다.
2. 어휘_문제1=10문제, 어휘_문제2=6문제, 독해_정보1=4문제로 표시되는지 확인합니다.
3. 3문제를 선택하여 풉니다. 선지를 고르지 않으면 제출되지 않아야 합니다.
4. 같은 선택을 빠르게 두 번 눌러도 풀이 한 건만 저장되어야 합니다.
5. 문제를 다시 풀 때 선택지 내용과 정답 표시가 일치하는지 확인합니다.
6. 제출 후 프로그램을 닫았다 열어 기록이 남는지 확인합니다.
7. 중간 종료 시 이미 제출한 문제만 기록되고 미제출은 오답 처리되지 않아야 합니다.
8. `Data 폴더 열기`로 새 파일을 넣고 저장 후 새로고침하여 반영되는지 확인합니다.
9. 디스플레이 배율 100%, 150%, 200%에서 버튼과 텍스트가 보이는지 확인합니다. 긴 문제와 선지는 스크롤해서 읽을 수 있어야 합니다.

## 재현 명령

```powershell
dotnet build QuestionBank.sln -c Release
dotnet run --project tests/QuestionBank.Checks/QuestionBank.Checks.csproj -c Release
```

검증용 임시 데이터는 OS 임시 폴더에 생성하고 삭제합니다. 사용자의 실제 `history.json`은 읽거나 수정하지 않습니다.
